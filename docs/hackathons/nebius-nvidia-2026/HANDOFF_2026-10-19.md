## 4. Current runtime limitation that motivated this work

AG-60 / Device Fabric is currently intentionally **read-only by default**.

Verified mutation policy blocks or gates operations such as:
- device reboot
- router/AP reboot without owner approval
- PoE cycle without owner approval
- VLAN changes
- DHCP changes
- firewall changes
- firmware changes
- PBX writes

Capability search on 2026-10-19 found normal read-only capabilities, but NO general persistent:
- `network.device.reboot.v1`
- `network.device.poe_cycle.v1`
- `network.device.verify_recovery.v1`

This is the core runtime gap to close.

Important architecture decision:

> **Dev Swarm is for DEVELOPMENT of these capabilities once. It must NOT be invoked every time AG-60 performs a normal runtime action.**

After implementation, AG-60 should call persistent Capability Gateway endpoints directly.

```text

  ->

  ->

  ->

  ->
```

Example judge story:

1. User asks InnerOS to inspect a building.
2. Device Fabric returns actual infrastructure state.
3. Nebius/NVIDIA reasoning identifies a likely degraded segment/device.
4. InnerOS proposes a bounded action.
5. Privileged action requires approval.
6. Local InnerOS node executes through the provider adapter.
7. InnerOS verifies recovery.
8. UI shows the evidence trail.

VoiceOps may be used only as a **human interface layer**, not as the core project.

## 7. Nebius/NVIDIA integration design

Nebius/NVIDIA is the reasoning provider, NOT the authority layer.

Required provider abstraction:
- Nebius/NVIDIA open model path for hackathon eligibility.
- Local model fallback remains available.
- Production InnerOS must not become hard-dependent on Nebius.

Reasoning request should consume a bounded/sanitized infrastructure state and return:
- diagnosis
- recommended action
- confidence/reason
- required capability
- whether approval is required

Execution remains local and governed by InnerOS.
