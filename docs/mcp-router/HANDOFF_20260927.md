## Required initial profiles
### profile_minimal
- Derive from canonical `chatgpt_compact`.
- Maximum 15 tools.
- Bootstrap, status, coordination, discovery.

### profile_coding
- Maximum 25 tools.
- Use real InnerOS tool names from the canonical catalog.
- Permit only scoped coding/repo/worktree/test/evidence capabilities.
- Risk metadata overrides name-prefix matching.

### profile_admin
- Disabled by default.
- Requires server-side client authorization and `ALLOW_ADMIN_PROFILE=true`.
- Full visibility never bypasses downstream approvals or mutation controls.

## Protocol requirements
Implement a real MCP proxy for:
- `initialize`
- `ping`
- `tools/list`
- `tools/call`

`tools/list` must return only the active profile's validated tools.
`tools/call` must deny any non-profile tool before forwarding.

Stable denied-call behavior:
- `ToolNotAllowedError`
- Session remains alive.
- Denied call never reaches backend.

## Security
The router is an additional deny layer, not a replacement for InnerOS security.

Requirements:
- Canonical path validation.
- Block traversal, null bytes, out-of-root paths, symlink escapes.
- Generic sandbox root: `/workspace`.
- Extra InnerOS worktree roots must be explicitly configured.
- Never allow unrestricted `/home/rlopez`.
- Never expose unrestricted shell/docker socket.
- Existing `local_exec_run_command_allowlisted` remains downstream authority.

## Throttling and cache
Implement:
- Per-client/profile request rate limits.
- Burst limits.
- Max concurrent `tools/call`.
- Catalog cache with TTL.
- Catalog fingerprint/version pinning.
- Fail closed on profile/catalog mismatch.

## Observability
Record only structured safe metadata:
- profile
- backend
- method
- backend tool count
- exposed tool count
- denied/forwarded counters
- gateway latency
- backend latency
- cache hit
- catalog pin
- error class

Do not log full secret-bearing arguments.

## Shadow rollout
1. Unit tests.
2. Router starts on `:8103` while production clients remain on `:8102`.
3. Real MCP test client validates protocol.
4. One isolated test client uses router.
5. Independent verification.
6. Only then prepare production cutover.

Rollback: stop router and point client back to `:8102`.

## Acceptance targets
- Monolith remains healthy on `:8102`.
- Router initializes on `:8103`.
- `profile_minimal <= 15`.
- `profile_coding <= 25`.
- No unauthorized tools visible.
- Denied calls never reach backend.
- Allowed read-only calls match backend semantics.
- Unauthorized admin blocked.
- Traversal/symlink/out-of-root blocked.
- Throttle does not disconnect session.
- Catalog change invalidates/revalidates cache.
- Gateway forwarding overhead target: p95 <= 20 ms local, excluding backend work.
- Cached `tools/list` target: p95 <= 50 ms.
- Persist direct-vs-filtered catalog size and serialized JSON reduction.
