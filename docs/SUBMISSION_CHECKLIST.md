# All Things Agentic Hackathon Submission Checklist

Last verified from connected Devpost source: 2026-08-25.
Submission deadline: **2026-09-01 00:00 UTC**. Re-read live Devpost rules/announcements before final submission.

## Product positioning
Target category: **Fortified Enterprise Fleet** unless later evidence/strategy explicitly changes it.

Why InnerOS/ARIA fits: enterprise agent registry/catalog, long-running execution, persistent context, tenant identity and gateway controls, approval/audit posture, observability, and production data/tool integration.

## Mandatory technology evidence
- [ ] Gemini 3.5 or newer through Gemini API or Vertex AI is implemented and demonstrable.
- [ ] At least one Google Agent Framework is implemented: ADK, Google GenAI SDK, Antigravity SDK or GenKit.
- [ ] At least one Google Cloud infrastructure service is implemented and deployment proof captured. Cloud Run/Firestore are natural existing choices.
- [ ] Repository clearly identifies where each required Google component is used.
- [ ] Demo captures visible Google Cloud deployment evidence (Cloud Run dashboard/logs/run.app URL or equivalent).

Local-first development remains the default; hackathon-required Google components are competition/runtime requirements, not permission to route ordinary coding work to paid external models.

## Submission artifacts
- [ ] Category selected.
- [ ] Hosted project URL supplied if stable enough; strongly encouraged, not globally required.
- [ ] Description covers features/functionality, technologies, other data sources, findings/learnings.
- [ ] Code repository URL supplied.
- [ ] If repository is private, required judge accounts are granted access.
- [ ] README contains reproducible local/cloud spin-up and testing instructions.
- [ ] Architecture diagram prepared in an accepted upload format.
- [ ] Approximately 4-minute demo video prepared.
- [ ] Video shows problem, value proposition, application in action and backend running on Google Cloud.
- [ ] Required Devpost custom fields completed, including project start date and Google SDK/model/cloud service declarations.

## Judging optimization
Current criteria:
1. Innovation & Operational Utility: 40%. Show autonomous high-value action, decisions and completed workflows with minimal hand-holding.
2. Architectural Discipline & Tech Stack: 30%. Show decoupling, state/memory, credential security, tenant boundaries and failure handling.
3. Demo & Production Readiness: 30%. Show a live/credible demo, architecture diagram, reproducible repo and visible Google Cloud proof.

Every implementation priority should strengthen at least one of these criteria. Avoid polishing low-value modules while a mandatory technology or demo proof remains missing.

## Bonus opportunities
- [ ] Public build article/podcast/video explicitly created for entering the hackathon.
- [ ] Public social post with the required hackathon hashtag wording verified again before publishing.
- [ ] Additional Google AI model integration (for example Gemma, Veo or Lyria) only if it adds demonstrable value and does not threaten core completion.
