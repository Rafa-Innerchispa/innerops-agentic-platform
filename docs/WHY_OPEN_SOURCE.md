# Why InnerOS is Open Source

InnerOS is open source because the durable coordination problem is bigger than any one company and because implementation quality is easier to trust when the architecture, tests, and failure modes can be inspected.

## What InnerChispa gains

### Trust

Customers, partners, judges, and developers can verify what the platform actually does instead of relying on a pitch deck.

### Distribution

Open repositories are discoverable through GitHub, search engines, technical communities, hackathons, research discussions, and downstream projects.

### Public proof of work

The repository becomes a permanent technical record of how InnerOS handles:

- durable agent execution;
- MCP tool routing;
- local-model failover;
- Temporal/LangGraph integration;
- bounded execution;
- recovery;
- observability;
- human approval.

### Faster engineering

Reusable open-source components can replace custom infrastructure where they are better. Public contributors can find bugs, propose integrations, and improve documentation.

### Recruiting and partnerships

A serious public codebase makes technical capability visible to engineers, vendors, accelerators, customers, and potential partners.

### Commercial leverage

The code can be open while the difficult operational work remains valuable:

- deployment;
- integration;
- enterprise support;
- managed operations;
- customer-specific connectors;
- hardware;
- security hardening;
- migrations;
- training;
- private business modules.

### Better hackathon positioning

A public project with real history, tests, architecture decisions, and production lessons is stronger evidence than a disposable demo repository.

## What stays private

Open source does not mean publishing everything.

Keep private:
- credentials;
- customer data;
- internal business records;
- private infrastructure topology;
- production secrets;
- customer-specific configurations;
- commercial modules that are intentionally proprietary;
- operational datasets;
- private prompts or processes that contain confidential information.

## The strategic moat

The moat is not a hidden Python file.

It is the combination of:
- brand;
- deployment experience;
- customer relationships;
- operational data;
- integrations;
- reliability;
- support;
- hardware footprint;
- accumulated architecture knowledge;
- speed of execution.

The public code makes the platform easier to trust and adopt. The business is built around delivering outcomes with it.
