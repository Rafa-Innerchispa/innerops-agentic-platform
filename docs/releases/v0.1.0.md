# InnerOS v0.1.0 - Durable Local-First Agent Operations

**Status:** release candidate notes prepared. Final tag should be cut only after the public release gate is satisfied.

## Why this release matters

Most agent systems are optimized around a live prompt-response loop. InnerOS v0.1.0 focuses on what happens when work becomes operational:

- tasks outlive chat sessions;
- workers fail;
- models become unavailable;
- tools need authorization;
- long-running workflows wait for people or external systems;
- duplicate state creates false completion;
- code must converge to one canonical history;
- execution needs evidence.

This release establishes the first public InnerOS platform baseline for durable, local-first agent operations.

## Highlights

### Durable workflows with Temporal

InnerOS uses Temporal as the durable execution authority for retries, waits, cancellation, recovery, and long-running workflow lifecycle.

### LangGraph reasoning

LangGraph provides structured reasoning/state graphs inside agent execution while Temporal remains responsible for durable workflow ownership.

### Bounded MCP capabilities

The platform is converging from a large monolithic tool surface toward compact, policy-aware MCP capability routing.

### Local-first inference

InnerOS supports heterogeneous local inference with AMD vLLM and Ollama-based fallback paths, with optional cloud providers behind the same operational boundaries.

### Event and observability spine

NATS JetStream and OpenTelemetry provide event distribution and correlated execution evidence across the durable coordination path.

### Safer execution

The platform includes bounded execution patterns, approval boundaries, Docker sandboxing, task ownership controls, and fail-closed behavior for high-risk operations.

### Evidence-driven completion

Software work is not complete merely because an agent reports success. The public workflow now defines completion in terms of tests, PRs, merge-to-main, exact SHAs, runtime reconciliation, and evidence.

## Architecture baseline

```text
Signals
  -> NATS / event intake
  -> Temporal durable workflow
  -> LangGraph reasoning
  -> MCP bounded capability
  -> local model or deterministic executor
  -> verification/evidence
  -> OpenTelemetry trace
  -> Mongo projection
  -> human approval when required
```
